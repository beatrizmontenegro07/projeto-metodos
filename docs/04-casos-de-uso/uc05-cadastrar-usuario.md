# UC05 — Cadastrar usuário

[← Casos de uso](README.md)

| Campo | Descrição |
|---|---|
| **Identificador** | UC05 |
| **Importância** | Essencial |
| **Sumário** | Permite que o Administrador cadastre quem pode entrar no CliniCore, com nome, e-mail, login, senha e papel. Num sistema sem usuários, permite criar o primeiro Administrador. |
| **Atores** | Administrador |
| **Pré-condições** | O ator está autenticado (UC04) com o papel Administrador. Sem sessão, o sistema leva à tela de login. |
| **Fluxo principal** | 1. O ator escolhe "Novo usuário" na lista de usuários (TL02) ou na página inicial (TL07).<br>2. O sistema exibe o formulário de cadastro (TL01).<br>3. O ator informa nome completo, e-mail, login, senha e escolhe o papel (Administrador, Recepcionista, Médico ou Paciente).<br>4. O ator escolhe "Cadastrar".<br>5. O sistema valida o papel, o login (RF08) e a senha (RF09).<br>6. O sistema grava o usuário com o e-mail em minúsculas e apenas o hash da senha (NF-SEG-01).<br>7. O sistema volta à lista de usuários (TL02), com o novo usuário no fim. |
| **Fluxos alternativos** | FA1 — Primeiro Administrador (RF16): enquanto não há usuários, a tela de login leva à tela "Crie o primeiro administrador" (TL06, `/setup`). Qualquer pessoa informa nome, e-mail, login e senha; o sistema aplica as mesmas regras dos passos 5 e 6, grava o usuário com o papel Administrador, abre a sessão dele e exibe a página inicial (TL07). Depois disso, `/setup` leva à tela de login.<br>FA2 — Cancelar (passo 4): o ator escolhe "Cancelar" e volta à lista de usuários sem gravar nada. |
| **Fluxos de exceção** | FE1 — Login inválido (passo 5): o sistema mostra junto do login "Informe o login.", "O login deve ter no máximo 12 caracteres." ou "O login não pode conter números.".<br>FE2 — Senha inválida (passo 5): o sistema mostra junto da senha "A senha deve ter pelo menos 8 caracteres.", "A senha deve ter no máximo 128 caracteres.", "A senha deve ser diferente do login.", "A senha deve ser diferente do e-mail." ou "A senha deve conter pelo menos três tipos de caracteres: minúsculas, maiúsculas, números e símbolos.".<br>FE3 — Papel inválido (passo 5): "O papel do usuário é inválido.".<br>FE4 — E-mail ou login repetido (passo 6), inclusive com outras maiúsculas no e-mail ou em cadastros simultâneos: "Já existe um usuário cadastrado com este e-mail." ou "Já existe um usuário cadastrado com este login.".<br>Em FE1 a FE4, o sistema mantém os valores digitados, exceto a senha, que nunca volta para a tela, e retorna ao passo 3.<br>FE5 — Primeiro Administrador já criado (FA1): "O primeiro administrador já foi criado. Entre com sua conta.", com o atalho "Ir para o login".<br>FE6 — Papel sem permissão (passo 1): para quem não é Administrador, o menu não mostra "Usuários" e `/users/new` exibe "Acesso negado — Seu papel não permite abrir esta página."; pela API, `POST /api/users` responde 403 com "Seu papel não permite esta operação.".<br>FE7 — Falha do armazenamento (passo 6): "Não foi possível acessar os dados agora. Tente novamente." (NF-CON-01). |
| **Pós-condição** | O usuário fica gravado com um identificador único e pode entrar no sistema (UC04) com o login ou o e-mail e a senha; ele aparece na listagem (UC06) e no total de usuários da página inicial (UC10). |
| **Requisitos** | RF07, RF08, RF09, RF16, NF-SEG-01, NF-SEG-02, NF-MAN-01, NF-CON-01 ([`specs/usuarios`](../../openspec/specs/usuarios/spec.md)) |
| **Telas** | TL01 Cadastro de usuário, TL02 Listagem de usuários, TL06 Primeiro administrador ([interface](../06-interface/README.md)) |

**No código:** a página `src/app/[locale]/(app)/users/new/page.tsx` envia o formulário à Server Action `addUser`, que chama `FacadeSingletonController.addUser`; a fachada verifica a permissão `MANAGE_USERS` e delega a `UserController.add`. O primeiro Administrador passa por `createFirstAdministrator` (`src/app/[locale]/(auth)/actions.ts`) e `UserController.addFirstAdministrator`. As mesmas operações estão em `POST /api/users` e `POST /api/auth/first-administrator`.
